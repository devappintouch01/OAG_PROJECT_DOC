## 5. ข้อควรระวัง / ความเสี่ยง (DISSENT)
- **สิทธิ์ข้ามศูนย์:** ปัจจุบันตัวค้นหาและตัว save ล็อกศูนย์ไว้เพราะกัน "ข้อมูลรั่วข้ามหน่วย" (ดู comment 36452-36459) การเปิดให้เลือกศูนย์ต้องตรวจฝั่ง server ทุกจุด ไม่งั้นผู้ใช้ปกติยิง request เปลี่ยนศูนย์เองได้ (blast radius = ข้อมูล PO/PR ของทุกศูนย์ใน department)
- **ใบเดียวกันปนหลายศูนย์:** ถ้า header เป็นศูนย์ A แต่ผู้ใช้เลือก PO ของศูนย์ B ในใบเดียวกัน ส่วนปิดรอบ/ interface EBS (`SaveBudgetReserved(id)`, ConfirmBudgetReserved) ที่อ่านศูนย์จากหัวใบหรือจาก account code อาจไม่ตรงกัน → ควรกำหนด **หนึ่งใบ = หนึ่งศูนย์ต้นทุน** (เลือกก่อนแล้วล็อก) ซึ่งตรงกับหน้า `BudgetOverlapYearCentralDetail` ที่ dropdown เปิดเฉพาะใบใหม่
- **กันซ้ำ:** ปัจจุบันกันซ้ำเฉพาะใบ dept+costcenter เดียวกัน ถ้าสองศูนย์เปิดใบแทนกันและเลือก PO เดียวกัน (PO ศูนย์ 0025 เปิดจากศูนย์ 0001 และจากศูนย์ 0025 เอง) ใบสองใบอาจเลือก PO ซ้ำ → ถ้าใบถูกสร้างด้วยศูนย์ของ PO ตามที่เลือกใน dropdown จะกันซ้ำได้ตามเดิม (แนะนำให้ศูนย์ของใบ = ศูนย์ของ PO)
- **ใบเก่า/สิทธิ์การดูรายการ:** รายการใบ P (`GetBudgetReservedList` API 36302) กรองตาม department ไม่กรองศูนย์ ผู้ใช้ในหน่วยเดียวกันจึงเห็นใบของกันและกันอยู่แล้ว ไม่ต้องเปลี่ยน
- **รายงาน/หน้าพิจารณา:** ถ้ามีที่ใช้ `Costcenterid` ของหัวใบเป็นเจ้าของ จะเห็นศูนย์ที่เลือก (ไม่ใช่ศูนย์ผู้ใช้) ยังไม่ได้ไล่ตรวจรายงานทั้งหมด
- **ทดสอบ:** ผมไม่ได้รันหน้าจอใด ๆ ในงานนี้ ต้องทดสอบที่ PREPROD ด้วย PO ที่ศูนย์ต่างจากผู้ใช้ (ใน PREPROD ต้องมีข้อมูล PO ศูนย์อื่นใน department เดียวกัน — ยังไม่ได้ตรวจ)
