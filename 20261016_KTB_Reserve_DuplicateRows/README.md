# KTB ส่วนเงินกัน (TRANSFERTYPE 2) ออกแถวซ้ำ + แถบบัญชีธนาคารไม่ sum ยอด

วันที่: 2026-10-16 · หน้าจอ: `BudgetOverlapYearPO` (กันเหลื่อมปี ส่วนหน่วยงาน) · ใบตัวอย่าง: เลขที่เงินกัน 69120001

## ปัญหา 1 — แถบบัญชีธนาคารเอายอดแค่แถวแรกของเลขที่เอกสาร (แก้ในโค้ด, TFS)

`BudgetOverlapYearPO.cshtml` เรียก `.DistinctBy(item => item.Booknumber)` ก่อน `GroupBy(...).Sum(...)`
แต่ละกลุ่มจึงเหลือแถวเดียว ยอดออกมาเป็นยอดของแถวแรก และยอดนี้ถูกบันทึกลง
`OAGWBG_BUDGETRESERVED_BANKACCOUNT.TOTALTRANSFERAMOUNT` ด้วย ซึ่งเป็นยอดที่ใช้โอนผ่าน KTB

แก้แล้ว: ยอดรวมจากแถวกันเหลื่อม (`ListOverLapId`) เท่านั้น ไม่รวมแถวขยายเวลา/ส่งคืน
เพราะเป็นแถวลูกที่ยอดซ้ำกับแถวแม่ ถ้ารวมด้วยจะนับซ้ำ

| ใบ | ก่อนแก้ | หลังแก้ | ยอดที่บันทึกใน DB |
|---|---|---|---|
| 69120001 (ID 40) — 4 แถว เลขที่เอกสาร 26900274 | 15,063.40 | 367,400 | ยังไม่มี |
| 681230 (ID 2) — 25 แถว × 128,828 | 128,828 | 3,220,700 | 3,220,700 |
| 681253 (ID 17) — แม่ + ขยายเวลา + ส่งคืน | 24,600 | 24,600 | 24,600 |

ตรวจโดยดึง JSON จริงจาก API `GetBudgetReservedDetail` แล้วรัน LINQ เดิมกับ LINQ ใหม่เทียบกัน

## ปัญหา 2 — `OAGWBG_R_KTBPAYMENT` ส่วนเงินกันคูณแถวตามจำนวน item (DDL, รันเอง)

ส่วน TRANSFERTYPE 2 ใช้ `LEFT JOIN OAGWBG_BUDGETRESERVEDITEM BRI ON BRI.BUDGETREVERSEDID = r.ID` เพื่อเอาแค่ `BUDGETPLANID`
แถวบัญชีจึงถูกคูณตามจำนวน item ในใบ และ entity `OagwbgRKtbpayment` เป็น `HasNoKey()` EF จึงส่งแถวซ้ำออกไปในไฟล์ KTB ครบทุกแถว

| ใบ | ยอดที่ควรโอน | ไฟล์ KTB เดิม |
|---|---|---|
| 681230 (ID 2) | 3,220,700 | 25 แถว = 80,517,500 |
| 681253 (ID 17) | 24,600 | 3 แถว = 73,800 |

แก้: เปลี่ยน BRI เป็นตารางย่อย `GROUP BY BUDGETREVERSEDID` + `MAX(BUDGETPLANID)` (1 แถวต่อใบ)
ตรวจแล้วใน PREPROD ไม่มีใบไหนที่ item มี `BUDGETPLANID` มากกว่าหนึ่งค่า `MAX` จึงได้ค่าเดิม

### ผลทดสอบที่ PREPROD (รันตัว SELECT ของ DDL ใหม่ ยังไม่ deploy)

| TRANSFERTYPE | view เดิม | DDL ใหม่ |
|---|---|---|
| 1 | 4,831 | 4,831 (แถวเหมือนกันทุกแถว) |
| 2 | 77 (ยอดรวม 971,361,688) | 29 (ยอดรวม 524,291,528 = ตารางบัญชี) |
| 3 / 4 / 5 | 14 / 21 / 16 | 14 / 21 / 16 (แถวเหมือนกันทุกแถว) |

ส่วนที่ 2 ทำ MINUS ทั้งสองทางได้ 0 แถว คือแบบใหม่ต่างจากเดิมแค่ไม่มีแถวซ้ำ

## ข้อควรระวัง

- DDL ทั้งสองไฟล์สร้างจาก view ของ **PREPROD** ก่อนรันที่ PROD ต้องดึง `DBMS_METADATA.GET_DDL('VIEW','OAGWBG_R_KTBPAYMENT','OAGWBG')` ของ PROD มาเทียบกับ `rollback_R_KTBPAYMENT.sql` ก่อน (PROD กับ PREPROD เคยเป็นคนละเวอร์ชัน)
- ยอดที่บันทึกผิดไว้แล้วใน `BUDGETRESERVED_BANKACCOUNT` (ถ้ามีใน PROD) จะไม่แก้เอง ต้องเปิดใบนั้นแล้วกดบันทึกใหม่ด้วยโค้ดที่แก้แล้ว
- ใบ 681230 (สถานะ 20202 ไม่ล็อก) ตอนนี้หน้าจอเดิมแสดง 128,828 ถ้ามีคนกดบันทึกก่อน deploy โค้ดใหม่ ยอดใน DB จะถูกเขียนทับเป็น 128,828
