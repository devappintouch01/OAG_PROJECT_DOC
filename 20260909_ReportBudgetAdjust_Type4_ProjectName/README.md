# รายงานการเปลี่ยนแปลงงบประมาณประจำปี — v5 (2026-09-09)

## โจทย์

1. เรียงลำดับแถวใหม่ — DR ขึ้นก่อน CR โดย **DR = ฝั่งรับโอน / CR = ฝั่งโอนออก**
2. ประเภท 4 (เบิกแทนกัน) ให้ **คำอธิบายรายการ / ประเภทรายจ่าย / รายการงบประมาณ** มีค่า
   โดยดึงจาก `OAGWBG_ACCOUNT_SEGMENT` ที่ `REFERENCETABLE = 'BudgetRequisition'`

---

## 1. ลำดับการเรียง (แก้ที่โค้ด ไม่แตะ view)

ย้ายการเรียงจาก DB query ไปทำตอนสร้างชีต — `ReportService.SortSheetRows()` เพราะ
1 ชีต = 1 ประเภทการโอน จึงใช้คีย์ต่างกันตามประเภทได้

**ประเภท 1 / 2 / 3 / 5**

```
เลขที่โอน → DR/CR → ปีงบประมาณ → รหัสแหล่งเงิน → แหล่งเงิน → แผนงาน → ผลผลิต
→ กิจกรรม → ประเภทรายจ่าย → รายการงบประมาณ → จำนวนเงินรับโอน → จำนวนเงินโอนออก
```

**ประเภท 4 (เบิกแทนกัน)** — ยังไม่ได้ระบุคีย์มา คงลำดับเดิม (DR/CR เป็นคีย์นอกสุด
→ มิติงบประมาณ → เลขที่โอนปิดท้าย)

`ROLETYPE` แปลงเป็นลำดับ: `'RECEIVER'` (รับโอน = DR) = 0, `'SENDER'` (โอนออก = CR) = 1
view ไม่มีคอลัมน์ DR/CR ตรง ๆ

> เรียงในหน่วยความจำ ไม่ใช่ที่ DB — แถวถูก `ToListAsync()` มาก่อนหน้าอยู่แล้ว
> query เหลือ `OrderBy(Roundno)` ไว้แค่ให้ผลจาก DB คงที่

## 2. 3 คอลัมน์ท้ายของเบิกแทนกัน (แก้ที่ view — v5)

v3/v4 ปล่อยทั้ง 3 คอลัมน์ของประเภท 4 เป็น `NULL` โดยอ้างว่า "ไม่มีข้อมูลจริงให้ดึง"
ข้อสรุปนั้น**ถูกครึ่งเดียว** — ตันเฉพาะเส้นทาง `CATEGORYID` เท่านั้น

| ช่องบนหน้าจอ (โมดัล "เพิ่มรายการงบประมาณ") | คอลัมน์ใน ACCOUNT_SEGMENT | lookup | คอลัมน์ใน view |
|---|---|---|---|
| คำอธิบายรายการ (`name="Description"`) | `DESCRIPTION` | — | `ITEMDETAIL` |
| ประเภทรายจ่าย (`name="Budgettypeid"`) | `BUDGETTYPEID` | `OAGWBG_V_EXT_OAGGL_BUDGET_TYPE_V` | `BUDGETTYPENAME` |
| รหัสงบประมาณ (`name="Budgetcodename"`) | `BUDGETCODENAME` | `OAGWBG_V_EXT_OAGGL_BUDGET_CODE_V` | `CATEGORYNAME` |

lookup ทั้งสองตัวเป็น master ที่ `ID = CODE` (VARCHAR2) จึง join ตรง ๆ กับค่าใน
`ACCOUNT_SEGMENT` ได้ ไม่ต้องแปลง — เป็น 2 view เดียวกับที่ dropdown บนหน้าจอใช้
(`MasterService.GetBudgetType()` / `GetBudgetCode()`)

### ทำไมไม่ใช้ CATEGORYID เหมือนประเภทอื่น

ตรวจ PREPROD 2026-09-09 — `OAGWBG_ACCOUNT_SEGMENT` ที่ `REFERENCETABLE='BudgetRequisition'`
มี 14 แถว `CATEGORYID` เป็น `'0000'` ทั้งหมด และ `'0000'` **ไม่มีอยู่ใน**
`OAGWBG_V_EXT_OAGINV_CATEGORY_CODES_V` (query คืน 0 แถว) เส้นทางนั้นตันจริง

แต่ `DESCRIPTION` **ไม่ได้เป็น 'โอนออก' ทุกแถวแล้ว** อย่างที่ v3 บันทึกไว้ — ตอนนี้มี
7 ค่าไม่ซ้ำ ครบ 14/14 แถว (ข้อมูลงอกหลังจาก v3 ตรวจไว้เมื่อ 2026-09-07)

## ผลข้างเคียงที่ตั้งใจ

`ReportService` มี logic `useBanner` — ถ้าทั้งชีตมี `ITEMDETAIL` ค่าเดียว จะขึ้นเป็น
banner แถว 2 ("รายการ : ...") แทนที่จะเป็นคอลัมน์

ประเภท 4 ที่เดิม `ITEMDETAIL` เป็น NULL หมดจึงไม่เคยมีคอลัมน์ "รายการ" เลย หลัง v5
จะเริ่มมี — และเพราะ `DESCRIPTION` เป็นข้อมูล**รายบรรทัด** (ไม่ใช่ระดับใบเหมือน
`BUDGETTRANSFER.ITEMDETAIL` ของประเภทอื่น) ชีตเบิกแทนจะขึ้นเป็น **คอลัมน์** เกือบทุกครั้ง
ไม่ใช่ banner

## ลำดับการ deploy

v5 ไม่ได้เพิ่ม/ลบคอลัมน์ แค่เปลี่ยนค่าใน 3 คอลัมน์ท้ายของประเภท 4 จึง **ไม่ต้อง**

```
1. รัน OAGWBG_R_BUDGETADJUST_deploy.sql   ← ทำแล้วบน PREPROD 2026-09-09
2. รัน verify.sql
```

Rollback: รัน `OAGWBG_R_BUDGETADJUST_rollback.sql` (คืนเป็น v4) — rollback โค้ดแยกอิสระได้
