## ⚠️ ลำดับสำคัญมาก — DDL ก่อน แล้วค่อย JS

**ห้ามขึ้น JS ก่อน DDL** ถ้าทำกลับด้านจะกู้ข้อมูลไม่ได้ถาวร:

```
JS ขึ้นก่อน (view ยังเก่า):
  แถวที่ควรกู้ได้ → view เก่าคืน NULL → จอแสดง "0.00"
  ใครกดบันทึก 1 ครั้ง → เขียนทุกแถวทั้งฟอร์ม (วัดได้จริง 951 แถว/คลิก)
  JS ใหม่ส่ง parsePrice("0.00") = 0   ← ส่ง 0 ไม่ใช่ null
  DB สร้าง type-4 row ค่า 0
  พอขึ้น view ใหม่ → COALESCE(0, 59,010) = 0   ❌ fallback ถูกบล็อกถาวร

DDL ขึ้นก่อน (JS ยังเก่า):
  จอแสดงค่าที่กู้มาถูกต้องทันที ✓
  กดบันทึก → JS เก่าส่งค่าจริง (truthy) → เขียนลงแถวใหม่ ✓ self-heal ทำงาน
  ผลข้างเคียงเดียว: คนที่ตั้งใจใส่ 0 จะถูกส่งเป็น null แล้วค่าเก่าเด้งกลับ
                    (เห็นได้ทันที และหายไปเมื่อขึ้น JS)
```

ให้ช่องว่างระหว่าง DDL กับ JS สั้นที่สุด ถ้าทำได้ควรอยู่ใน maintenance window เดียวกัน

### STEP 4 — JS (ทันทีหลัง STEP 3 ผ่าน)

ไฟล์: `OAGBudget/Views/Budget/BudgetRequestSummaryDetail.cshtml`

```diff
  const $grandChild = $(this);

+ const $kept = $grandChild.find('.detail-Totalkeptcentral');
+ const keptRaw = $kept.length ? $kept.val() : null;
+ const keptIsEmpty = keptRaw === null || keptRaw === undefined || String(keptRaw).trim() === '';
+
  const data = {
      ...
-     totalkeptcentral: parsePrice($grandChild.find('.detail-Totalkeptcentral').val() || 0) || null,
+     totalkeptcentral: keptIsEmpty ? null : parsePrice(keptRaw),
```

แก้ไว้ใน workspace แล้ว **build ผ่าน 0 Error** (1,685 warning เดิม ไม่เพิ่มใหม่) — **ยังไม่ checkin รอ review**

**ทำไมต้องมี:** เดิม `|| null` ทำให้ค่า `0` ถูกส่งเป็น `null` ระบบจึงแยกไม่ออกระหว่าง
"ตั้งใจใส่ 0" กับ "ไม่เคยกรอก" — พอมี fallback แล้ว คนที่ตั้งใจล้างค่าเป็น 0
จะเห็นค่าเก่าของคำขอแม่เด้งกลับมา
