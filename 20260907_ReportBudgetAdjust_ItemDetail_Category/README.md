# รายงานการเปลี่ยนแปลงงบประมาณประจำปี — v3 (2026-09-07)

## โจทย์

1. หัวรายงานให้ปรับตามชื่อประเภทการโอนที่เลือก
2. กรณีโอนเปลี่ยนแปลง — เพิ่มช่อง "รายการ" (ดึงจากคำอธิบายรายการ), "ประเภทรายจ่าย", "รายการงบประมาณ"
3. กรณีโอนปรับเงินเหลือจ่าย — เพิ่มช่องเหมือนกัน และแก้บั๊ก "รายการโอนออกไม่ออก"

## ที่มาของข้อมูล

| ช่องบนรายงาน | คอลัมน์ใน view | ต้นทาง |
|---|---|---|
| รายการ | `ITEMDETAIL` | `OAGWBG_BUDGETTRANSFER.ITEMDETAIL` |
| ประเภทรายจ่าย | `BUDGETTYPENAME` | `OAGWBG_V_EXT_OAGINV_CATEGORY_CODES_V.BUDGET_TYPE_NAME` |
| รายการงบประมาณ | `CATEGORYNAME` | `OAGWBG_V_EXT_OAGINV_CATEGORY_CODES_V.NAME` |

> ประเภทรายจ่ายใช้ **BUDGET_TYPE_NAME ไม่ใช่ EXPENSE_TYPE_NAME** — ค่าที่ผู้ใช้ต้องการคือ
> "ค่าใช้สอย - รายการไม่ผูกพัน" / "เงินรายได้สะสม" ซึ่งอยู่ใน BUDGET_TYPE_NAME
> ส่วน EXPENSE_TYPE_NAME เป็นชั้นบนกว่า ("ค่าใช้จ่ายดำเนินงาน") และมีค่าว่างหลายแถว

## บั๊ก "รายการโอนออกไม่ออก" ของประเภท 3

ฝั่งโอนออกของโอนปรับเงินเหลือจ่ายไม่ได้อยู่ใน `OAGWBG_BUDGETADJUST`
(ตรวจ PREPROD 2026-09-07 — type 3 มี 0 แถวในตารางนั้น) แต่อยู่ใน
`OAGWBG_BUDGETRECEIVEREFUND` โดย `SaveBudgetReservedTransfer` ขั้น 3.4
เขียน 1 แถวต่อ 1 กองเงินต้นทางที่ถูกตัด — `GIVERID` ชี้กลับไปแถวต้นทางใน
`OAGWBG_BUDGETRECEIVE`, `TOTALREFUNDAMOUNT` คือยอดที่ตัดจริง

v3 เพิ่ม UNION branch ตามเส้นทางนี้

## ตัวกรองปีงบประมาณ — เปลี่ยนไปกรองจาก 2 หลักหน้าของเลขที่โอน (แก้รอบ 2)

หลัง deploy v3 แล้วฝั่งโอนออกของประเภท 3 ยังไม่ขึ้นบนรายงาน สาเหตุคนละตัวกับ view:

โอนปรับเงินเหลือจ่ายเป็นใบโอนที่ **คร่อม 2 ปีงบประมาณ** — ฝั่งโอนออกคือเงินเหลือจ่ายของปีเก่า
(`BUDGETYEAR` 2568) ส่วนฝั่งรับโอนถูกตั้งเป็นกองของปีใหม่ (2569) ตรวจ PREPROD: type 3
มี 23 จาก 26 แถวรับโอนที่ปีไม่ตรงกับปีของใบโอน

`ReportBudgetAdjust` เดิมกรอง `x.Budgetyear == model.BudgetYear` รายแถว → เลือกปี 2569
ได้เฉพาะฝั่งรับโอน ฝั่งโอนออกหายทั้งใบ

แก้เป็นกรองจาก **2 หลักหน้าของ `ROUNDNO`** (เลขที่โอน = ปี 2 หลัก + orgtype + running
เช่น `6810001` = ปี 68) — เลือกปีงบ 68 ได้เฉพาะเลขที่โอน `68xxxxx`

ตรวจ PREPROD 2026-09-07: `ROUNDNO` เป็นเลข 7 หลักเสมอ (min/max length = 7) และ 2 หลักหน้า
เป็นปีงบทุกประเภทรวมถึงเบิกแทน (`BUDGETREQUISITION.RUNNING`)

ข้อดีคือฝั่งโอนออก/รับโอนของใบเดียวกันใช้ `ROUNDNO` ร่วมกัน จึงออกมาพร้อมกันเสมอ
และไม่มีใบไหนโผล่ซ้ำในรายงาน 2 ปี

### Layout ใหม่ของชีต

```
แถว 1  หัวรายงาน (merge ทั้งแถว) — ชื่อตามประเภทการโอนที่เลือก
แถว 2  "รายการ : <คำอธิบายรายการ>" (เฉพาะกรณีทั้งชีตมีคำอธิบายเดียว)
แถว 3  เว้นว่าง
แถว 4  หัวตาราง
แถว 5+ ข้อมูล / แถวสุดท้ายเป็นยอดรวม
```

คอลัมน์: ลำดับ, เลขที่โอน, [รายการ], หน่วยเบิกจ่าย, ศูนย์ต้นทุน, ปีงบประมาณ, รหัสแหล่งเงิน,
แหล่งเงิน, แผนงาน, ผลผลิต, กิจกรรม, **ประเภทรายจ่าย**, **รายการงบประมาณ**,
จำนวนเงินรับโอน, จำนวนเงินโอนออก

"รายการ" จะเป็นคอลัมน์เฉพาะตอนที่ชีตมีหลายใบโอนที่คำอธิบายไม่เหมือนกัน
ถ้าเลือก "เลขที่โอน" มาใบเดียว (คำอธิบายเดียว) จะขึ้นเป็น banner แถว 2 แทน
ไม่งั้น banner ใบเดียวจะโกหกแทนใบอื่นทั้งชีต

## ลำดับการ deploy (สำคัญ)

**ต้อง deploy view ก่อนโค้ด** — ถ้าโค้ดใหม่ขึ้นก่อน view จะได้ `ORA-00904: invalid identifier`
เพราะ EF จะ SELECT คอลัมน์ ITEMDETAIL / BUDGETTYPENAME / CATEGORYNAME ที่ยังไม่มี

```
1. รัน OAGWBG_R_BUDGETADJUST_deploy.sql
2. deploy โค้ด
```

Rollback: รัน `OAGWBG_R_BUDGETADJUST_rollback.sql` (คืน view เป็น v2) **พร้อมกับ** rollback โค้ดด้วย
