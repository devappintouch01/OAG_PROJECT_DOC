## สาเหตุ

```csharp
TopThreeByAmount = g.OrderByDescending(x => x.PlanAmount).Take(3)      // ต่อ 1 รายการ
var sortedByMonth = d.TopThreeByAmount.OrderBy(x => x.Month).ToList();
m1 = sortedByMonth.ElementAtOrDefault(0)?.Amount ?? 0m;   // → คอลัมน์ F เสมอ

```

โค้ด **ไม่ได้ map ยอดเข้าเดือน** — แค่เอาของที่เลือกมาวางลงช่องที่ 1/2/3 ตามลำดับ

รายการที่มีข้อมูลไม่ครบ 3 เดือน ยอดจึงถูกดันมาชิดซ้าย
เช่น BG `73466` มีแถวเดียว (เดือน 9 ยอด 129,360) → ตกไปอยู่ `m1` = คอลัมน์ **F = ก.ค.**

ซ้ำร้ายหัวคอลัมน์เดือนอ่านจาก `firstItem` **แถวเดียว** (บรรทัด ~8588) แล้วใช้กับทั้งชีต
หัวคอลัมน์กับตัวเลขในแถวจึงไม่ได้ผูกกันเลย

## การแก้ (ทางเลือก A — คงคอลัมน์ 3 เดือนไว้เท่าเดิม)

**เลือกเดือนที่ระดับ "ทั้งคำขอ" ครั้งเดียว แล้วหยอดยอดเข้าช่องของเดือนตัวเอง**

```csharp
// 1) ดึงมาทุกแถว ยังไม่ตัดเดือนทิ้ง
var rawData = ... .Select(d => new { BudgetGovernmentId, Month, Amount });

// 2) เลือกเดือนของทั้งคำขอ เรียงตามปีงบประมาณ (ต.ค. → ก.ย.)
var pickedMonths = rawData.Select(x => x.Month).Distinct()
    .OrderBy(m => m >= 10 ? m - 12 : m).Take(3).ToList();

// 3) หยอดยอดตามเดือนจริง ไม่มีเดือนนั้นก็เป็น 0
static decimal AmountOfMonth(Dictionary<int, decimal> byMonth, int? month) =>
    month.HasValue && byMonth.TryGetValue(month.Value, out var amount) ? amount : 0m;
```

และ `Month1/2/3` ของทุกแถวใช้ `pickedMonth1/2/3` ชุดเดียวกัน
→ โค้ดวาดหัวคอลัมน์เดิมที่อ่านจาก `firstItem` จึงถูกต้องอัตโนมัติ **โดยไม่ต้องแก้**

### สิ่งที่ไม่ได้แตะเลย

- โค้ดวาด Excel ทั้งหมด

## ข้อจำกัดที่ยังเหลือ (รับทราบและยอมรับแล้ว)

**คำขอที่วางแผนเกิน 3 เดือน ยังแสดงได้แค่ 3 เดือน** — ปีงบ 2569 มี **85 คำขอ (31%)**
ในจำนวนนี้ **31 คำขอวางครบ 12 เดือน** (หาย 9 เดือน)

การแก้ถาวรต้องทำคอลัมน์เดือนแบบไดนามิก ซึ่งกระทบเลย์เอาต์ทั้งตาราง
(`TOTAL_COLS`, สูตรรวม, ตำแหน่งคอลัมน์ ประมาณการคงเหลือ/ขอเพิ่ม/คำอธิบาย,
ความกว้างคอลัมน์ และ `PageSetup.FitToPages(1, 0)` ที่จะบีบ 21 คอลัมน์จนอ่านไม่ออก)
— แยกเป็นงานรอบถัดไป

## ประเด็นที่ยังไม่ได้แก้ในรอบนี้

**1. แยกเป็น 2 ก้อน ทั้งที่แผนงาน/ผลผลิต/กิจกรรมเดียวกัน** (ยังเห็นที่แถว 38–44)

BG `73466` (cat 2194) และ `73472` (cat 26127) หา `CODE_COMBINATION_ID` ไม่เจอ
โค้ดจึง `continue;` ทิ้ง → ตกกลุ่ม `"ไม่ระบุ Template"` → ตั้งก้อนใหม่ + พิมพ์ผลผลิต/กิจกรรมซ้ำ

ตรวจแล้วเป็น**ข้อมูลฝั่ง Oracle** ไม่ใช่บั๊กการประกอบ segment — account code ที่ประกอบได้
(บัญชีย่อย `210003` / `210024`) ไม่มีทั้งใน `OAGGL_ACCOUNT_HIERARCHIES_V` และ
`GL_CODE_COMBINATIONS_KFV` เพราะศูนย์ต้นทุนยังไม่เคยมีงบบนบัญชีย่อยนั้น

**ทางแก้ที่เสนอไว้:** เมื่อ leaf CCID = 0 ให้หา `TEMPLATE_NAME` ด้วย **prefix segment 1–8**
(`หน่วยเบิกจ่าย.ศูนย์ต้นทุน.ปี.แหล่งเงิน.แผนงาน.ผลผลิต.กิจกรรม.ประเภทงบ`) แทนการ `continue`

หลักฐานว่าปลอดภัย — สแกน `OAGGL_ACCOUNT_HIERARCHIES_V` ทั้งตาราง:

| ตัดที่ | จำนวน prefix | prefix ที่มี TEMPLATE_NAME > 1 ค่า |
|---|---|---|
| seg 1–10 | 10,804 | **0** |
| seg 1–8 | 3,589 | **0** |

`TEMPLATE_NAME` ถูกกำหนดครบด้วย segment 1–8 — บัญชีย่อยและรหัสงบประมาณไม่มีผล
(แต่ `BUDGETTYPEID` seg 8 อย่างเดียวไม่พอ — ค่า `212001` โยงไป 134 Template)

ขอบเขต: ปีงบ 2569 มี **2,220 แถว ใน 423 คำขอ** ที่ leaf ไม่เจอแต่ prefix เจอ
และอีก 548 แถวที่ไม่เจอทั้งสองแบบ

**2. คอลัมน์ "ประมาณการคงเหลือ"** มีอยู่แล้วในซอร์ส (`=E-I`) แต่ไม่มีบนแถว
"งบรายจ่าย" กับ "ประเภทค่าใช้จ่าย" เพราะ 2 แถวนั้นไม่มียอด B–E

**3. การเลือก rule ไม่ deterministic** — `candidates.FirstOrDefault()` ได้แถวตามลำดับที่ DB คืนมา
และ category `26127` มี `BUDGETYEAR = NULL` ทำให้เงื่อนไขตรงเป๊ะไม่มีวันแมตช์
